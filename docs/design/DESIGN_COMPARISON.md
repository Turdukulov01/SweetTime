# Сравнение дизайн-прототипов SweetTime

> **Решение (2026-07-08): выбран дизайн №2 (`../sweettimetwo/`).** Он скорректирован под фичи SweetTime: сомы, филиалы Бишкека, чекаут самовывоз/ко времени/QR, лояльность 5%/30%/12 мес, рефералка 50/100, постоянный заказ с предоплатой (день/неделя/месяц), OTP-мок, гостевой профиль, нижняя таб-навигация; админка убрана из клиентского меню. Итоговые токены и правила — в [DESIGN_SYSTEM.md](DESIGN_SYSTEM.md). Скриншоты `d2-*` обновлены и показывают скорректированную версию; `d1-*` — исходный дизайн №1.

Дата: 2026-07-08. Оба прототипа — Next.js веб-макеты, используются как **дизайн-референс для Flutter-приложения** (решение зафиксировано). Скриншоты: [screens/](screens/) (`d1-*` — дизайн №1, `d2-*` — дизайн №2, мобильный вьюпорт 390×844, админки — 1366×900).

## Где что лежит и как запустить

| | Дизайн №1 «sweetime-bubble-tea» | Дизайн №2 «sweetime-storefront» |
|---|---|---|
| Путь | `sweetime/` (внутри репо) | `../sweettimetwo/` |
| Запуск | `npm run dev -- -p 3001` → http://localhost:3001 | `pnpm dev -p 3002` → http://localhost:3002 |
| Установка | `npm install --legacy-peer-deps` (next 15.0.3 против react 19) | `pnpm install` |

## Визуальный стиль

| | Дизайн №1 | Дизайн №2 |
|---|---|---|
| Палитра | Пастель: cream `#FDF6ED`, pink `#F6B8C4`, berry `#5B2A3A`, mint `#9BDCC8`, caramel `#DDB878` | Ярче: cream `#fffaf0`, candy `#ff5c9a` (hot pink), mint `#34c99a`, coffee `#7b4b35` |
| Шрифты | Fraunces (display) + Plus Jakarta Sans + IBM Plex Mono для цен | Inter везде |
| Фирменные детали | «Жемчужины тапиоки»: PearlLoader, pearl-rise анимация, blob-радиусы | SVG drink-art, float-анимации, glow-тени, брендированные PNG стаканов «SWEETIME» |
| Впечатление | Спокойная пастель, ближе к «kawaii, но не перегружено» из UX-брифа | Более «маркетинговый» глянец, крупный hot-pink акцент |

⚠️ **Шрифты дизайна №1 не поддерживают кириллицу** (Fraunces и Plus Jakarta Sans — только latin). Русские тексты сейчас рендерятся системным fallback. Запрошенный сабсет `cyrillic` вообще ронял сервер 500-ками — убран в [layout.tsx](../../sweetime/src/app/layout.tsx). При выборе №1 нужна замена шрифтовой пары на кириллическую.

## Качество кода как базы

- **№1**: 14 товаров в мок-данных, типизированный домен (`types/index.ts`), API-слой `lib/api.ts` под замену на backend, контексты Cart/Auth/Theme, дизайн-токены в tailwind-конфиге, README с описанием дизайн-системы. Минусы: фото — случайный Unsplash (часть не совпадает с напитком: у «Браун-шугар боба» фото салата), hero-картинка не грузится, устаревшие пины зависимостей (npm ставится только с `--legacy-peer-deps`), на `/cart` в dev-режиме всплывает 1 ошибка Next.js.
- **№2**: чище и свежее по конфигам (pnpm, tokens.css как отдельный слой), 8 товаров, свои PNG-фото стаканов + SVG drink-art (нет проблемы «чужих» фото). Минусы: покрытие экранов заметно уже, admin/auth — по одной странице.

## Рекомендация

**Взять дизайн №1 как основу** и перенести в него лучшее из №2.

Почему №1:
1. Покрытие Screen Inventory из UX-брифа в разы полнее (auth-flow с OTP, гостевые состояния, полная админка, пагинация, отзывы) — меньше строить с нуля.
2. Пастельная палитра ближе к направлению «пастель/kawaii, но чисто» из брифа; №2 с hot-pink `#ff5c9a` выглядит эффектно, но дальше от ТЗ.
3. Данные уже под Бишкек: +996 в auth, точки Чуй/Манаса/Bishkek Park, кыргызские имена в админке.
4. Админка №1 почти повторяет структуру будущего React Admin — можно использовать как спецификацию.

Что забрать из №2 при коррекции:
- брендированные фото стаканов и SVG drink-art вместо случайного Unsplash;
- блок «Сезонные акции» на главной;
- уровни лояльности в профиле;
- слой `tokens.css` (CSS-переменные) — удобнее конвертировать в Flutter-токены.
