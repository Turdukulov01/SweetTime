# Совместная работа ИИ-ассистентов (Claude Code + Codex)

Здесь хранится оперативный контекст двух ассистентов, которые могут работать над SweetTime
отдельно и одновременно.

## Выбранная схема

Используются **два авторских файла** и один общий файл правил:

- `CLAUDE_NOTES.md` — пишет только Claude Code, читает Codex;
- `CODEX_NOTES.md` — пишет только Codex, читает Claude Code;
- `README.md` — общий протокол; менять только для улучшения самого процесса сотрудничества.

Два авторских файла выбраны потому, что они сохраняют авторство выводов и уменьшают риск
одновременной перезаписи. Это особенно важно, пока проект не находится под Git. Общий контекст
обеспечивается обязательным взаимным чтением, одинаковой структурой и ссылками между записями.

## Источники правды

1. `docs/TASKS.md` — единственный канонический backlog, порядок работ и статус приёмки.
2. `docs/PROJECT_BRIEF.md`, `docs/UX_UI_BRIEF.md`, `docs/FEATURE_PRIORITIES.md` и
   `docs/IMPLEMENTATION_PHASES.md` — утверждённые продуктовые рамки и фазовый порядок.
3. `docs/design/*` — детальные проектные материалы. Пока Task 2 из `docs/TASKS.md` не принят,
   найденные в них расхождения должны записываться как противоречия, а не считаться молча
   утверждёнными решениями.
4. Файлы `*_NOTES.md` — оперативная память, анализ и передача работы. Они не заменяют backlog,
   не разрешают переход к следующей фазе и не подтверждают приёмку задачи пользователем.

Если источники расходятся, ассистент фиксирует противоречие в своём файле и следует более
консервативному статусу из `docs/TASKS.md` до решения пользователя.

## Обязательный цикл работы

В начале каждой сессии ассистент:

1. читает `AGENTS.md`, `docs/TASKS.md`, этот файл и файл коллеги;
2. проверяет дату заметок коллеги и не принимает устаревшие заявления без повторной проверки;
3. сверяет активные зоны коллеги со своей задачей и не начинает пересекающуюся запись без
   явного поручения пользователя;
4. обновляет в своём файле текущую задачу и зоны записи до существенных изменений.

После значимой работы ассистент обновляет свой файл:

- что было сделано и какие файлы изменены;
- какие проверки запускались и каков результат;
- что осталось, что заблокировано и какое решение нужно;
- новые находки по дизайну, Flutter, admin, backend, инфраструктуре и безопасности;
- риски, опасности, противоречия, идеи и предложения;
- вопросы или просьбы к коллеге.

## Правила безопасного обмена

- Никогда не редактировать файл заметок коллеги.
- Не считать утверждение коллеги доказанным, если оно конфликтует с тестами, кодом или
  `docs/TASKS.md`; записать расхождение спокойно и со ссылкой на источник.
- Не менять активную зону коллеги без явной задачи пользователя. Запрос на координацию писать
  в своём файле и сообщать пользователю.
- Для свежей находки использовать идентификатор владельца: `CX-###` для Codex и `CL-###`
  для Claude Code. Ссылаться на него из другого файла, не копируя весь текст.
- Статусы находок: `новое`, `проверяется`, `предложено в TASKS`, `принято`, `решено`,
  `устарело`.
- Актуальные секции можно переписывать. Журнал выполненной работы ведётся добавлением коротких
  датированных записей, чтобы не терять историю до появления Git.
- Не хранить секреты, токены, реальные пароли или персональные данные.
- Писать на русском, кратко и проверяемо; даты — `ГГГГ-ММ-ДД`, пути — от корня проекта.

## Одинаковая структура авторских файлов

1. Текущий статус и активные зоны.
2. Выполнено с последнего обновления: файлы, проверки, результат.
3. Следующие и ожидающие задачи со ссылками на `docs/TASKS.md`.
4. Анализ по областям: продукт/дизайн, Flutter, admin, backend, инфраструктура/QA/безопасность.
5. Активные риски, опасности и противоречия с идентификаторами и статусами.
6. Идеи и рекомендации.
7. Просьбы и вопросы к коллеге.
8. Краткий журнал значимых изменений.
